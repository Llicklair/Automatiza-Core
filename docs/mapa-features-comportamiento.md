# Mapa de features y comportamiento — AutomatizaCore

> Generado el 2026-06-30 por un barrido multiagente (14 módulos). Por cada feature se contrasta el **comportamiento exacto** (camino preprogramado/determinista: fallbacks, defaults, gates de autonomía, scheduler) con el **comportamiento esperado** del LLM. El símbolo ⚠ marca divergencias clase "Switch Pro" (el determinista diverge en silencio de lo que el usuario/IA espera).

## Índice de módulos
- Marketing y Redes Sociales
- Facturacion (Verifactu/AEAT)
- Contabilidad
- Banca y Conciliacion
- CRM
- RRHH y Nóminas
- Inventario y Stock
- Documentos, Escaner e Importacion
- Compliance y Configuracion Fiscal (AEAT)
- Seleccion de Personal (Reclutamiento)
- Email y Correos
- RAG / Informes IA / Busqueda
- Analítica, Alertas y Auditoría
- Motor de pre-programadas (Orquestador/Scheduler) + Gate de Autonomia

## Patrones transversales
- Tools gateadas bajo CONFIRM/MANUAL que no crean nada, mientras docstring y system prompt prometen exito (campana programada, horario aplicado, conciliacion hecha): el LLM informa de un exito que no ocurrio. Afecta marketing(create_campaign), hr(propose_schedule), banking(reconcile_transactions).
- Dominios marcados CONFIRM en autonomy.DEFAULTS cuyo gate NUNCA se aplica al camino real: el agente ejecuta directo via _run_graph_agent/ToolNode sin evaluate_autonomy. Afecta accounting, documents, recruitment, email; ademas import N43/auto-match por REST salta el gate banking_write=MANUAL que si bloquea al agente.
- El gate de autonomia solo cubre el camino del LLM, no la UI/REST ni los workflows desatendidos; y puede bypassearse si no se resuelve tenant_id (autonomy_gate.py:230-236). La barrera de seguridad tiene huecos sistematicos por canal.
- Fallbacks deterministas que ignoran o sustituyen el input del usuario presentandolo como exito: marketing (catalog[:3] en vez del producto pedido, post-espejo forzado), orquestador (heuristica de plan vacio que ejecuta 'chat'/keyword), event_bus (_infer_domain a 'billing').
- Errores tragados convertidos en texto/success=True: el fallo viaja como string que el LLM presenta como respuesta normal, o se sintetiza success=True. Afecta payroll(asiento), embeddings(RAG), classify_document, contabilidad(PeriodClosedError), recruitment(detect_failure por texto), dispatch compliance, scheduler(no-op '[PENDIENTE]', fallo no critico, aprobacion sin kind).
- Sustitucion silenciosa de datos reales por inventados/demo/cero presentados como fiables: informe contable 'datos plausibles', banca _DEMO_SALDOS, email modo DEMO '[DEMO] enviado', metricas marketing a cero como dato real, time_saved DEFAULT_MINUTES.
- Contrato frontend/dispatcher desalineado: el front lee campos (answer/sources_used/respuesta_consulta) que el dispatcher output={action,response} nunca rellena, descartando la respuesta real del agente sin error visible. Afecta RagChatBox y ConsultaTab (compliance).
- Operaciones de stock/CV/adjuntos/PDF que omiten parte del trabajo en silencio: batch_adjust_stock sin FEFO/lock, extract_cv_data persiste candidato vacio, adjuntos de email omitidos, lineas de factura sin match, deduct_fefo shortage, dedup de informes que pisa, clamp a 0 de stock por almacen.
- Simulaciones/placeholders cableados a la UI como si fueran la accion real, mientras el implementador robusto existe pero esta desconectado: mark_verifactu_sent (vs VerifactuSubmitter.submit real sin caller), scoring de CV deshabilitado documentado como activo.
- Promesas de accion en prompts/textos de tool que no tienen camino de ejecucion (read-only disfrazado de accion) o features de UI que aparentan integracion IA inexistente: qualify_leads 'puedo mover automaticamente', badge 'Generado por IA' sin fuente, buscador de Actividades decorativo.
